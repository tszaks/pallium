# v0.10.0 — Source-bound project knowledge

Pallium's knowledge base now separates source freshness, mechanical citation
checks and model audit assessments. Editing a file cannot leave its old prose
looking current, and linked worktrees no longer overwrite each other's indexes.

## For agents and users

- Compact version-2 search returns five excerpts within 8 KB. `knowledge context`
  and MCP `pallium_knowledge_context` provide task context within 12 KB, including
  source paths, related tests and suggested checks. Full legacy payloads remain
  available with `--full`; get supports `--section`.
- Tracked Markdown, SQL, configuration and shell sources join the code map.
  `.pallium/modules.json` can preserve module boundaries, exclude sources and
  explicitly include individual untracked files. Untracked trees and session
  histories are not imported automatically.
- `knowledge decisions link` imports explicit authored decisions with provenance,
  visible conflicts and explicit supersession. Reindexing preserves them.
- `knowledge serve` opens a local, responsive browser for search, source evidence,
  audit outcomes and maintenance controls, with light and dark themes.
- Opt-in `knowledge maintain` runs after the editor closes. Its persistent queue
  and call ledger live in the existing Pallium global database. Model attempts
  share a hard 40-call rolling daily cap, two active slots and three-minute
  deadlines. Errors and unknown costs remain visible.

## Correctness and trust

Directory IDs no longer collide when punctuation and nesting differ. Symbol
citations require exact module/receiver identity; ambiguous names are rejected.
Scanners mask comments/literals and recognize multiline JS/TS imports and class
methods with implementation spans. Go partial parses and scanner limitations are
reported. Audits retain timestamps and per-claim verdicts, including supported
outcomes, and may make one bounded evidence expansion before keeping uncertainty.

Generated documents retain history. The first knowledge-v2 migration backs up an
existing knowledge database; generated Markdown uses atomic file replacement and
preserves authored pages. Incident keyword matches are labeled candidates.
Neither a resolving citation nor a model audit is proof that prose is true.

## Compatibility and migration

Run `pallium index` and `pallium knowledge build --no-model` after upgrading.
Legacy docs remain readable as needing rebuild. Use returned module IDs rather
than constructing old dash-separated slugs. Index linked worktrees separately.
The deprecated read field `verified` is true only for a current, audit-supported
document. Search/context are versioned; map/list responses use compact envelopes.

Enable maintenance only for repositories whose source you intend the configured
provider to read. The first build and all audits obey the same global cap; a large
repo can have pending work after its first day. No initial-build bypass exists.

## Validation and limits

The controlled Go/TypeScript/Swift corpus found the expected module in the top
three for all 30 questions. A 2,000-file development fixture measured warm retrieval
p95 below 250 ms. Two paired agent tasks used about 96% less supplied context while
both variants answered correctly; no latency improvement was demonstrated.
These measurements do not establish broad task-success or token-cost savings.

Release assets are prepared on a draft release before public visibility. The npm
trusted-publishing workflow requires all four public archives and their checksum
manifest. Published assets are verified rather than rebuilt or overwritten.

For rollback, stop maintenance, preserve the current databases/WAL files and
restore `pallium.sqlite.pre-knowledge-v2` if using an older incompatible binary.
Keep the previous binary. Public fixes ship under a new version and tag.
